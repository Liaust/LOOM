# MINA Workflow

Use this as a task reference, not a required sequence of context/tool calls.

LOOM, Basecamp and Provenance are core peers: source/technical state,
commitments/work state, and qualified shared meaning respectively. Use what the
task needs, not all three on every turn. Hermes memory is conversational context,
not a replacement for any of them.

- Start with the requested outcome and owning source. Follow its applicable
  instructions; reuse already-loaded context while its trusted scope and
  revision remain unchanged. Known source uses filesystem tools directly.
  Choose other retrieval surfaces for missing information. Independent reads
  may run in parallel; no fixed search/get order is required for navigation.
- Implement authorised project work directly, including substantial features
  and repairs, in the current task at that project's source. Workers and
  worktrees are optional; a separate integrator or coding agent is not required.
  Load
  `protocols/PROJECT-DELEGATION.md` only when a handoff is actually useful
  and authorised; the broad workspace is not the project's code root.
- Load `protocols/SESSION-RETRIEVAL.md` only for needed conversation history,
  or `protocols/PROVENANCE-AND-MEMORY.md` when durable meaning matters. Neither
  replaces current source or runtime evidence. Use `TOOLING.md` for a missing
  tool detail, not as a preamble to every command.
- Deliver notes/files at their canonical source for the operator's Loom desktop
  app. Give its verified Main and Box-relative paths, not a separate Obsidian
  vault/export unless requested. App browsing does not require indexing;
  local/offline copies and protection remain separate facts.
- Carry out the ordinary means of the task under `OPERATING-POLICY.md`, with
  a proportionate plan/check. Verify the requested result, distinguishing
  source edits, installation, live effects and protection.
- Maintain relevant Basecamp commitments, progress, blockers and needed input
  when ordinary work changes them, even without an explicit Basecamp request.
  Search before creating accepted follow-ups or unfinished work; omit routine
  steps completed in the same turn. Apply `protocols/BASECAMP.md` and its actor
  preflight. GitHub/code updates follow `protocols/GITHUB.md`; they do not
  replace Basecamp task state. Reuse unchanged instructions. Use
  `handoffs/HANDOFF-TEMPLATE.md` for an actual handoff, not every small edit.
- Consult Provenance when prior decisions or constraints matter. Capture
  source-backed durable decisions, preferences, constraints, corrections
  and unresolved questions with `use-loom-provenance` and
  `loom provenance candidate register`. Keep actual MINA producer attribution, source
  posture and the receipt. No quota for routine edits or chatter. Reconcile
  relevant meaning now when needed; do not wait for a background schedule to
  discover decisions that were never registered.

Resolve the relevant uncertainty with a focused check. Hold only the dependent
effect when actual scope, identity, ownership, permission or source state is
missing; continue independent work and give one actionable blocker. Do not turn
a failure into broader access, a new profile, an invented command, or an
unbounded repair loop. Follow existing rollout authority without asking again
for each stage; `OPERATING-POLICY.md` owns the remaining effect boundaries.
