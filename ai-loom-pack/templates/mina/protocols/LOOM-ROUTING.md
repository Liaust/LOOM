# LOOM Routing

Load this reference for a knowledge/project-state detail, not every source read.
The quick surface choices live in `DEVICE-AND-TOOL-ROUTING.md`; use a known
route directly. Reuse the reference while its trusted scope/revision is unchanged.

LOOM supplies sources, knowledge and technical project/runtime state. Basecamp
owns commitments, task/Kanban state and human calendar events. Provenance owns
qualified shared meaning. All are core; use the relevant owner rather than
routing every question through LOOM search or calling every surface in sequence.

the operator normally browses and edits original project files in the Loom desktop
app, with folder focus available. Give the verified Main path and Box-relative
path. Do not export an Obsidian vault or create a second notes tree for access.
Desktop browsing, local/offline availability, indexing/enrichment and protection
are independent; preserve processing/download pauses and qualify mobile access.

For technical project/repository ownership use `loom project list`,
`loom project inspect` or `loom project repos list` as needed. For a repository
implied by purpose, topics or focus use `loom provenance repo list`, then get
the selected exact reference. Neither is a prerequisite to a known source edit.

An ordinary source read needs no search skill, docs lookup, indexing wait or
node-health preflight. An empty indexed search does not prove file absence.

Use another surface for a missing piece, not a compulsory call order.
Independent retrievals may run in parallel; unrelated engine scores are not
interchangeable and separate reads need not share a snapshot. Preserve result
identity, source posture, currentness, truncation and evidence. Pending candidates require
explicit inclusion and remain unaccepted clues. Source documents and repository
contracts can correct a semantic navigation result.

Use authorized capabilities for actions inside LOOM. Worker controls belong to
supported LOOM worker surfaces. Native Codex owns native thread/worktree lifecycle;
Hermes owns its native agent and computer-use surfaces; ORCA is retired.
Never read database tables or call lifecycle storage internals to bypass either.

Notes search returns compact current files; `--details` is optional diagnostics.
Native text reads do not wait for extraction/embedding or require an Obsidian
binding. PDF/image reads use available current extraction and never start heavy
processing. Historical citation recovery is separate. The returned path belongs
to its node; normal task-authorized source-file work is not prohibited merely
because search found it. Preserve missing/unavailable and archived outcomes.

Provenance previews can answer navigation questions. Use a selected exact get
for needed meaning, evidence or lifecycle, and `--details --json` for the full
representation. Before a lifecycle write, obtain its required exact state;
routine output and stored source receipts grant no new action authority.
