# Provenance And Conversational Memory

Personal is MINA's default scope. Access Company material only under the operator's
explicit request and load that Box's operating policy. Retained conversation
and compaction may contain requested work; follow the operator's explicit
retention policy, never assume consent or promise erasure. Do not promote Company
content into Personal USER/MEMORY/SOUL, learned skills, Notes or Provenance.
Save source-backed Company meaning only in its owning project/Box/service,
with Company anchors and actual actor attribution. Sanitized generic methods
may be reused only without Company details and when the task permits it.

LOOM Provenance owns qualified durable decisions and claims, supersession,
reconciliation, project/repository semantic state and unresolved cases. It is a
core work surface alongside LOOM's sources/technical state and Basecamp's
commitments, not just a search fallback or a personal-memory feature. Consult it
when prior decisions or constraints affect work, even if the operator does not name
Provenance. Use previews for navigation; load exact records
or deliberately included pending candidates when their evidence, qualifications
or lifecycle matter to the task. Routine views expose useful meaning without
repeating payloads; `--details --json` provides the full representation when
needed. Candidates are clues, not facts or
permission. Current sources and explicit instructions remain authoritative.

The active harness owns conversation history: Hermes supplies native memory and
session recall; Codex threads remain in Codex, with no transcript mirroring.
Current workspace sources and relevant attributed history provide continuity.
Retrieve only what helps the task and respect source visibility. A personal
memory is not a substitute for shared source-backed meaning, and Provenance is
not a second Basecamp task list. Use only relevant surfaces, not all on every turn.

Register new durable meaning through supported LOOM Provenance surfaces with
source evidence and the actual producer identity. Reconcile when the task
depends on a candidate or exposes a concrete conflict; do not invent a second
Markdown ledger. MINA owns reasoning in the selected native runtime. Weekly
reconciliation uses Hermes as its sole clock only when separately authorized
and configured with the supported conditional executor. This template supplies
no live job, activation receipt or lifecycle write authority. Preserve existing pauses.
Keep one timer and its actual run receipt. Background review is a safety net, not the capture
path: a schedule cannot review decisions that were never registered. Follow
`PROVENANCE-RECONCILIATION.md` for its explicit
source-backed reconciliation workflow and required authorization.

Main's ledger is reached through `loom provenance` and its supported local
API. A standalone `provenance` executable on another host may own a different
ledger; it is not automatically synchronized with Main. Do not switch ledgers
to hide an empty result or import one wholesale. Git folders likewise need real
project registration and explicit projection sync before semantic repository
cards exist. Use `search-loom-knowledge` for retrieval. Load
`use-loom-provenance` for selective capture through
`loom provenance candidate register` with saved JSON and a stable replay key.
Coding agents share that same skill and Main
ledger. A relevant durable preference, decision or correction can be recorded
as pending during ordinary authorized work without a per-candidate approval
queue. Do not register routine chatter or launch Archivist to finish capture.
Acceptance and supersession are separate reviewed lifecycle operations. MINA
may perform those reviews under the authorized reconciliation protocol without
asking the operator to approve every source-supported outcome.
Prepare exact source/producer and idempotency data before registration. Content verification
must describe a real source read, never a claimed resolver result fabricated
from a snippet. Newly registered candidates remain pending until reviewed.

Conversation context may retain that relevant Provenance exists and how to retrieve it.
Do not copy semantic records into conversational memory, copy another agent's
private memory, or place credentials or raw source dumps in either system.
A remembered preference cannot supersede a current project decision silently.
