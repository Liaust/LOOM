# Provenance And Conversational Memory

Hermes owns session history, episodic/working memory and conversational context,
including preferences and relationship context with no stronger authoritative
home. Maintain native memory without a per-write approval queue under
`OPERATING-POLICY.md`. Retrieve only
what helps the current task and respect the source conversation's visibility.

LOOM Provenance owns qualified durable decisions and claims, supersession,
reconciliation, project/repository semantic state and unresolved cases. Search
there when those affect work; load exact records or deliberately included
pending candidates before interpreting them. Candidates are clues, not facts or
permission. Current sources and explicit instructions remain authoritative.

Register new durable meaning through supported LOOM Provenance surfaces with
source evidence and the actual producer identity. Reconcile when the task
depends on a candidate or exposes a concrete conflict; do not invent a second
Markdown ledger or replace the deterministic Archivist with a recurring agent.

Main's ledger is reached through `loom provenance` and its supported local
API. A standalone `provenance` executable on another host may own a different
ledger; it is not automatically synchronized with Main. Do not switch ledgers
to hide an empty result or import one wholesale. Git folders likewise need real
project registration and explicit projection sync before semantic repository
cards exist. Use `search-loom-knowledge` for retrieval. The installed LOOM CLI
exposes reads. Load `use-loom-provenance` for selective capture and its concrete
candidate-registration API recipe. Coding agents share that same skill and Main
ledger. A relevant durable preference, decision or correction can be recorded
as pending during ordinary authorized work without a per-candidate approval
queue. Do not register routine chatter or launch Archivist to finish capture.
Acceptance and supersession are separate reviewed lifecycle operations.
Prepare exact source/producer and idempotency data before registration. Content verification
must describe a real source read, never a claimed resolver result fabricated
from a snippet. Newly registered candidates remain pending until reviewed.

Hermes may remember that relevant Provenance exists and how to retrieve it.
Do not copy semantic records into conversational memory, copy another agent's
private memory, or place credentials or raw source dumps in either system.
A remembered preference cannot supersede a current project decision silently.
