# Session Retrieval

For Hermes conversations use native session recall or select the exact saved
session in Hermes Desktop/Hermex. Both clients reach Main's Hermes state.
Codex history is separate; there is no automatic transcript mirror. Do not
substitute an old Codex assignment for the current Hermes task after compaction.

Codex Desktop's remote Main project and direct Main Codex CLI share one
account's native CODEX_HOME. Mac-local chats use the Mac's own state. A shared
store does not make separate threads one continuous transcript.

Use cwd-filtered `codex resume` from the actual MINA workspace or selected
repository/worktree. `--all` deliberately broadens the list; it does not change
identity. Non-interactive scheduled exec threads may require
`--include-non-interactive`. Confirm the installed command's help before use.
Resume an exact selected thread ID, never `--last` or an assumed newest result.
Preserve thread ID, source cwd, relevant source visibility and task identity.

When native thread tools are available, list/filter by relevant cwd and use
supported thread reads for a selected ID. Do not inspect a runtime database or
parse every rollout to simulate a search service. The LOOM job result preserves
scheduled run-to-thread links. A CLI thread is not necessarily visible in a
Desktop Scheduled view; consult LOOM's run record for the schedule itself.

Project workers start fresh in their repo/worktree with project instructions;
do not fork a MINA conversation into a neutral worker. Profiles select settings,
not transcript isolation. Shared account state is not per-agent security custody.

Historical sessions remain attributed historical sources. Retrieve one
through its retained supported session-search surface when it materially helps;
do not silently import it or treat an old message as current authority. Never
query a session database directly or change retention, prune sessions or restore
an archive merely to answer a conversation. Report missing history honestly.
