# Project Delegation

Identify the owning repository from supported LOOM project/Provenance surfaces
and verify its current root contracts. Ordinary coding work belongs to a
project-root worker in the owning project's native worktree/task workflow.
ORCA owns interactive lifecycle; respect a repository's accepted Codex-managed
worker policy where it applies. Never create a competing LOOM task registry.

Give the worker the outcome, exact accepted base, canonical source root,
relevant planning files, expected files, forbidden systems, dependencies,
validation commands, checkpoint and stop conditions. Project workers read their
own `AGENTS.md`, `.loom/`, and `.repo/` contracts before editing.

Send task-relevant evidence and source pointers only. Do not give the worker
Morathustra's SOUL, Hermes memory or unrelated conversations, or imply that it
inherits a broader identity, credentials, permissions or operational authority.
Route a LOOM-core defect to the LOOM repository developer and production work
to its integrator/operator.

Review the committed handoff and verification evidence. Record unresolved work
in the owning canonical task/project system. A task assignment is not an
external commitment, merge, deployment or account authorization.
