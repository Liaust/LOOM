# LOOM Routing

Choose one first surface by the question, then inspect the exact chosen item:

| Question | First surface |
|---|---|
| Technical object identity, version, extraction or failure state | `loom object list` / `loom object inspect` |
| What a source says | `loom notes search` and the supported exact Notes get |
| Qualified decisions, preferences, constraints or unresolved cases | `loom provenance search`, then exact record/candidate/case get |
| Technical project/repository ownership or registration | `loom project list` / `loom project inspect` / `loom project repos list` |
| Repository implied by aliases, purpose, topics or focus | `loom provenance repo list`, then `loom provenance repo get` |
| How a supported command behaves | `loom docs search` and release-matched local help |

Expand sequentially only for a named gap. Preserve result identity, source
posture, currentness, truncation and evidence. Pending candidates require
explicit inclusion and remain unaccepted clues. Source documents and repository
contracts can correct a semantic navigation result.

Use authorized capabilities for actions inside LOOM. Worker controls belong to
supported LOOM worker surfaces; ORCA owns interactive agent/task lifecycle.
Never read database tables or call lifecycle storage internals to bypass either.
