# Archivist Workflow

1. Establish the question, project scope, and required source posture.
2. Route to one first engine: Objects for technical state, Notes for source
   material, Provenance for qualified state, or `loom project` for technical
   project and repository navigation.
3. Run one compact search or list operation.
4. Load the chosen item through its exact get or inspect surface.
5. State what is accepted, pending, unresolved, stale, or merely observed.
6. Expand sequentially to one additional engine only for a named evidence gap.
7. For candidate review, preserve an investigation and use the reviewed
   candidate protocol. Invoke the deterministic worker only as one explicit
   manual run.
8. Record the result in a bounded handoff when another owner or more evidence
   is required.

Never fan out across engines by default. Never infer acceptance from ranking,
source wording, producer identity, or a candidate's presence.

`project_state` is captured `.project` context, not accepted decisions. Follow
its snapshot-qualified exact get for evidence; missing Git or `.repo` does not
prevent project context. Automatic metadata refresh is not an Archivist run.
