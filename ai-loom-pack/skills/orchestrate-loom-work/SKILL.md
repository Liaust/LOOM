# Orchestrate LOOM Work

Coordinate the requested outcomes using their owning sources and current task
state. This skill supplies no personality, account identity or execution grant.
MINA keeps her workspace identity; a coding agent keeps its own project context.

## Work In The Current Task

Continue in the current task for focused work when its scope permits. Work in
the owning repository under its actual instructions; the broad MINA workspace
is not a substitute project root. Worktrees are optional for genuinely
independent parallel work, not prerequisites for an edit. Use an accepted plan
for larger work when the repository requires one.

The current agent can implement substantial features, fix defects, test and
integrate its authorized change. Coordination is not its only role. Do not hand
work to a coding agent or integrator merely because it is complex or involves
code. Coordinate actual overlapping owners and follow effect-based authority.

Create a separate chat only when the operator requests one. If independent work
is worth delegating, follow the current harness and repository policy; do not
invent a mandatory worker, formal slice or handoff for every small change.

## Use Current Sources

- Start from the operator's request, the relevant canonical task and owning files.
  Read known paths directly; use only the project context needed for the task.
- Use supported LOOM status when the question depends on runtime. Consult
  command help or relevant docs for a specific missing detail, not as a ritual.
- Use Provenance for relevant durable decisions or unresolved history, verified
  against current sources. Conversation or private memory is not task truth.
- Distinguish proposed, implemented, installed, observed and protected outcomes.
  A dated receipt or another agent's summary is not a fresh runtime observation.

## Harness And Worktree Ownership

Use the available native controls of the running harness. Codex owns its
threads and worktrees; Hermes owns its native agent sessions and routines. Give each managed
worktree one lifecycle owner. Another client may open its existing path without
creating a second managed checkout. LOOM adds no worktree or chat registry.

For Codex-owned work use Codex controls. For desktop work use the current
harness's native computer-use tools; Main-to-Mac uses the existing loom-mac
connector. ORCA and its legacy skills are retired, not an availability fallback.
A missing native tool remains unavailable; preserve device and permission boundaries.

## Coordinate When Needed

Map only the relevant dependencies, source roots, owners and blockers. Keep
facts, decisions and hypotheses distinct. Handle bounded work directly or
prepare a task-scoped handoff using [routing rules](references/routing.md).
Record outcomes and unfinished work in the canonical task/project state.

Do not pass MINA's SOUL, private memory, credentials or unrelated conversations
to workers. Assignment conveys only its actual parent-authorized scope, never
broader publication, contact, deployment, spending, destructive action or account
access. Complete already-authorized project rollout through supported tooling;
involve an operator or credential owner only for an actual missing effect or
access boundary, not an ordinary implementation checkpoint.
