# Routing And Handoff Rules

## Inventory Only What Matters

Read the known task and owning source first. Use `loom project list` for an
unknown project, or inspect/status for the exact project when identity/runtime
matters. Neither a whole-project inventory nor docs search is required before
ordinary code or file work. Use command help and relevant docs for an actual gap.

Follow the owning `AGENTS.md`; consult relevant `.project` context or
`.loom/project.yaml` when the work depends on it. Use the canonical task
interface only within the independently authenticated account/project.

## Routing Table

| Work | Primary owner |
| --- | --- |
| Ordinary project content, code or contracts | Current agent in the owning source; a project worker only when useful and authorised |
| LOOM core code or cross-project platform defect | Current agent may implement in the real LOOM checkout when that development scope is authorized; coordinate actual shared owners |
| Host update, rebuild, backup or restore | Actor authorized for that effect; an operator handoff is needed only when actual scope/access is missing |
| Ambiguous failure | Current investigator, narrowed to the failing layer |
| Credential value or Proton workflow | Approved credential owner/skill |
| Priority or external commitment needing the operator | the operator |
| Codex chat/worktree | Native Codex lifecycle owner |
| Desktop interaction | Native harness computer-use; existing loom-mac connector for Main-to-Mac. No ORCA fallback. |

## Proportionate Handoffs

A small delegated edit needs a bounded outcome, source root, relevant
instructions, appropriate checks and a concise result. No new planning files
or exhaustive file inventory are required unless the repository/task says so.

For planned or cross-owner work, add accepted scope, dependencies, actual
authority, validation/stop conditions and completion evidence. Keep identity,
current source, runtime observation and open questions explicit. Workers report
their branch/result; the integrator owns shared state and integration.

Pass only task-relevant context. Never include private global memory,
credentials, unrelated project data, hidden assumptions or implied account
authority. A handoff does not initialise MINA in a coding-agent session.
